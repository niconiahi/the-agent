# Architecture Skill

## When to Use

When the user wants to discuss, explore, and iterate on system design before any code is written or any plan is formalized.

## What This Is

A conversation mode for designing. No steps, no checklists, no implementation plans. Just talking through:

- What are the moving parts
- How they connect to each other
- What responsibilities each piece has
- What patterns make sense and why
- Trade-offs between approaches

## How It Works

1. **Present ideas conversationally** — explain what a piece does and why it exists, not how to build it
2. **Sell the design** — justify each moving part. If it can't be justified, it shouldn't exist
3. **Invite pushback** — the user drives. They accept, reject, or reshape ideas
4. **Iterate** — when the user challenges something, rethink it and come back with alternatives
5. **Stay high-level** — talk about interfaces, responsibilities, and data flow. Not line-by-line code

## What NOT to Do

- Do not write implementation plans (numbered steps, task lists)
- Do not write code unless the user asks for a small snippet to illustrate a point
- Do not create files
- Do not assume the design is final — it's a conversation, not a deliverable
- Do not dump everything at once. Present one idea at a time and let the user react

## When It Ends

The user decides. They'll say when they're sold and ready to move to implementation. Until then, keep designing.
